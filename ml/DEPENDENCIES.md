# Зависимости ML и зоны ответственности

ML — необязательный рекомендательный сервис. Backend владеет данными, допустимыми
кандидатами и изменениями состояния; ML принимает ограниченный снимок и возвращает только
ранжирование или `ABSTAIN`.

| Возможность | Текущий статус | Следующий подтверждаемый шаг |
|---|---|---|
| Report/Incident contract | Backend gateway и HTTP-контракт реализованы | Зафиксировать контракт финального release |
| Семантическая рекомендация «Другое» | Локальная E5-модель, exact-match и fail-closed fallback подключены | Накопить пользовательские подтверждения |
| Candidate filtering | Backend ограничивает дом, категорию, активность, окно времени и количество | Нагрузочно проверить на production-подобной БД |
| Decision persistence | Исход и допустимые candidate IDs сохраняются в `incident_grouping_decision` | При необходимости добавить снимок показанных score |
| Canonical address | `house_id` и FIAS/external IDs предоставляет ingestion | Не разрешать адрес средствами ML |
| Organization registry | Дома и справочные организации импортируются с provenance | Согласовать назначение справочной организации операторской записи |
| External events | Контракт допускает внешний контекст, production-источник не подключён | Не блокирует основной MVP |
| Category model | CPU TF-IDF baseline воспроизводимо обучается и вызывается по HTTP | Не автоматизировать решения до real/OOD test |
| Matching benchmark | 1 100 synthetic queries; отдельный набор `other-v1` | Добавить 50–100 независимо размеченных реальных сценариев |
| Calibration | ECE/Brier/risk-coverage считаются, пороги выбраны на validation | Повторить после заморозки human-reviewed test |
| Inference | health/readiness, classify/batch/decide/grouping и Docker реализованы | Измерить финальный образ и чистый запуск |
| Vision/OCR | Не реализовано | Вне обязательного MVP |

## Инварианты

- ML не создаёт Incident, не связывает Report и не меняет статусы.
- Backend передаёт только допустимые кандидаты и повторно проверяет выбор пользователя под
  блокировкой.
- Отсутствие данных или модели приводит к `ABSTAIN`/контролируемому fallback, а не к выдуманному ID.
- Hard safety rules и права доступа остаются в Backend.
- Score — сигнал ранжирования, а не вероятность, пока не выполнена калибровка.
- Секреты внешних API не сохраняются в наборах данных или manifest.

## Границы пакетов

- `src/ml` не импортирует SQLAlchemy-модели Backend.
- `src/domains/ml` не импортирует реализацию embedding-модели.
- UUID передаются по JSON строками, taxonomy — стабильными кодами.
- Локальные веса загружаются только из доверенного кеша и проверяемых артефактов.

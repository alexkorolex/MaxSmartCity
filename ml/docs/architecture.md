# Архитектура ML-модуля

## Почему в репозитории есть `src/ml`, `src/domains/ml` и `ml`

| Путь | Ответственность | Что туда не входит |
|---|---|---|
| `src/ml` | Исполняемый код stateless ML-сервиса | ORM и бизнес-переходы Incident Core |
| `src/domains/ml` | Backend gateway, выбор допустимых кандидатов и проверка HTTP-ответа | Веса, токенизация и реализация модели |
| `ml` | Конфиги, датасеты, контракты, метрики, скрипты и кеш артефактов | Импортируемый runtime-код |

Корневой каталог `ml` нельзя переносить внутрь `src/ml`: в нём находятся данные и артефакты,
а не исходный пакет. Совпадающее имя обозначает принадлежность ресурсов ML-контуру. Точки
входа всегда запускаются как модули `src.ml.*`, а пути `ml/*` передаются им как данные.

```text
domain       — стабильные снимки, результаты задач, обратная связь и типы асинхронных событий
application  — сценарии использования, оркестрация резервных решений и политика входных данных
ports        — интерфейсы моделей, backend и ingestion
adapters     — базовые правила, адаптеры моделей и заглушки зависимостей
data         — загрузчики, логика разбиения и генерация синтетического мира
training     — воспроизводимое обучение локальных baseline-моделей
evaluation   — метрики и нагрузочные benchmark-команды
inference    — проверенная загрузка артефактов и семантические рекомендации
service      — HTTP-граница процесса ML
```

Зависимости направлены внутрь: `domain` не импортирует `adapters`, `application` работает через
`ports`, а модели и интеграции заменяются без изменения доменных контрактов.

Асинхронность находится на границах системы:

```text
очередь backend / асинхронный HTTP
→ ограниченная очередь инференса
→ сборщик пакетов
→ синхронный адаптер модели
→ идемпотентное событие с результатом
```

Чистые преобразования, генераторы наборов данных, метрики и прямой проход модели остаются
синхронными. Транспорт HTTP реализован. Отдельная очередь не нужна для текущего синхронного
MVP: входные наборы ограничены контрактом, CPU-инференс вынесен из event loop, а сбой ML
приводит к контролируемому `ABSTAIN`/fallback без изменения Report или Incident.

# Инференс

Локальный smoke-test обученного category checkpoint:

```bash
uv run --locked python -m src.ml.inference.cli \
  --artifact ml/artifacts/category-tfidf-logreg-v2 \
  --text "В доме 12 третий час нет холодной воды"
```

Ответ содержит ранжированные category scores, `abstain`, причину отказа, model version и taxonomy
version. Пустой текст всегда приводит к `ABSTAIN`.

`joblib` нельзя загружать из недоверенного источника. Веса не коммитятся; локальный loader
проверяет SHA-256 модели и согласованность model/taxonomy version с manifest. Для передачи
checkpoint нужен доверенный artifact storage.

## Инференс по HTTP

После обучения:

```bash
uv run --locked litestar --app main:app run --host 0.0.0.0 --port 8000
```

Реализованы `/v1/classify`, `/v1/classify:batch`, `/v1/decide`, `/health`, `/ready` и
`/v1/models`. CPU inference выполняется вне event loop; `/v1/decide` соблюдает `deadline_ms` и
возвращает стабильные error envelopes. При отсутствии checkpoint health остаётся доступным,
readiness возвращает 503, а rule fallback сохраняет recommendation-only решение для backend.

Схемы wire-контрактов находятся в `ml/contracts/backend/v2`. Organization/action models пока
явно возвращают task-level `ABSTAIN`; rule incident ranking также не разрешён для автоматизации.

## Семантическая рекомендация для категории «Другое»

`POST /v1/grouping:recommend` ранжирует только те активные инциденты, которые backend заранее
ограничил по допустимой географии и временному окну. ML не создаёт инцидент, не меняет БД и не
переопределяет выбор жителя. Ответ содержит одну из рекомендаций:

- `ATTACH` — уверенное совпадение с достаточным отрывом от второго кандидата;
- `CLARIFY` — показать жителю возможный инцидент и запросить подтверждение;
- `CREATE` — предложить новый инцидент и короткое извлекаемое название;
- `ABSTAIN` — модель отключена, недоступна или вход небезопасно велик.

Локальный provider использует квантованный `multilingual-e5-small` (384 измерения, около 140 МБ)
через ONNX/FastEmbed. Установка для локальной разработки:

```bash
uv sync
```

FastEmbed входит в группу зависимостей `ml`, которую `uv sync` ставит локально по умолчанию.

Веса скачиваются в `ML_SEMANTIC_CACHE_DIR` и не коммитятся. Docker-образ ML загружает их на этапе
сборки, поэтому рабочий контейнер не обращается во внешнюю сеть. AITUNNEL остаётся только частью
offline-пайплайна синтетики.

Текущие пороги консервативны и требуют калибровки на размеченных реальных сообщениях. При любом
сбое основной сценарий продолжает работать через пользовательский выбор и Incident Core.

Для интеграции с общей PostgreSQL следующий шаг — `pgvector`: хранить centroid активного кластера,
версию embedding-модели, число сообщений и время последнего события. PostGIS сначала ограничивает
кандидатов по городу/радиусу, `pgvector` выбирает ближайшие, а ML применяет пороги и отрыв. Благодаря
этому не требуется полный перебор всех инцидентов города.
